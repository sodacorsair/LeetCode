You are given a palindromic string s and an integer k.

Return the k-th lexicographically smallest palindromic permutation of s. If there are fewer than k distinct palindromic permutations, return an empty string.

Note: Different rearrangements that yield the same palindromic string are considered identical and are counted once.

 

Example 1:

Input: s = "abba", k = 2

Output: "baab"

Explanation:

The two distinct palindromic rearrangements of "abba" are "abba" and "baab".
Lexicographically, "abba" comes before "baab". Since k = 2, the output is "baab".
Example 2:

Input: s = "aa", k = 2

Output: ""

Explanation:

There is only one palindromic rearrangement: "aa".
The output is an empty string since k = 2 exceeds the number of possible rearrangements.
Example 3:

Input: s = "bacab", k = 1

Output: "abcba"

Explanation:

The two distinct palindromic rearrangements of "bacab" are "abcba" and "bacab".
Lexicographically, "abcba" comes before "bacab". Since k = 1, the output is "abcba".
 

Constraints:

1 <= s.length <= 104
s consists of lowercase English letters.
s is guaranteed to be palindromic.
1 <= k <= 106

Thought:

🌟 Core Insight: Reducing the Palindrome to the "K-th Permutation of the First Half"

The problem asks for the $k$-th lexicographically smallest palindromic string. Since a palindrome is perfectly symmetrical, we don't need to permute the entire string; we only need to arrange its "first half."
The middle character (if the length is odd) and the second half are uniquely determined by the first half. Thus, the problem is elegantly reduced to a classic mathematical problem: Given a multiset of characters, find its $k$-th lexicographically smallest permutation.

🛠️ Algorithm Steps: Greedy Construction

We use a left-to-right, character-by-character greedy strategy to build the first half:

1. Count & Halve: Count the frequencies of all characters in the original string and divide them by 2 to create the "character pool" for our first half.
2. Iterative Trial: For each position in the first half, we try placing a character in lexicographical order, from 'a' to 'z'.
3. Branch Weight Calculation (Branch Prediction):
   Suppose we try placing character $X$. We use a mathematical formula to calculate how many distinct permutations can be formed by the remaining characters (let's call this total $W$).
    * If $W < k$: Even if we generate all permutations starting with $X$, we won't reach the $k$-th one. So, the current position cannot be $X$. We deduct $W$ from $k$ (i.e., skipping these $W$ permutations) and try the next character $Y$.
    * If $W \ge k$: The $k$-th permutation we are looking for must be located within this branch. We firmly "lock in" character $X$ for this position, break the loop, and proceed to the next position (keeping $k$ unchanged).

🚀 The Game Changer: Multiset Permutations with Upper-Bound Truncation

The formula for multiset permutations is:

$$W = \frac{L!}{c_1! \times c_2! \times \dots \times c_{26}!}$$

* The Pain Point: $L$ can be up to 5000. $5000!$ is an astronomical number that will easily cause overflow and Time Limit Exceeded (TLE) if calculated directly, even with BigInteger.
* The Ultimate Optimization: The constraints state $k \le 10^6$. This implies we don't actually need the exact value of $W$ if it's exceedingly large; we only need to know if it's strictly greater than $k$!

Therefore, we introduce two geek-level optimizations in our permutation calculation (getCount function):

1. Early Limit Break: During the iterative multiplication/division step (ways = ways * len / j), the moment ways exceeds $k$, we immediately return k + 1. This completely cuts off the astronomical calculations.
2. Max Count Skip: Don't start calculating from a base of $1$. We find the character with the highest remaining frequency (let's call it $MAX$), and completely skip its factorial calculation! We initialize len as $MAX$ and start accumulating from the other characters. This not only prevents overflow but also triggers the "early break" in extremely few steps, effectively crushing the time complexity of this calculation down to $O(1)$.

⏱️ Complexity Analysis

* Time Complexity: $O(N \times \vert{}\Sigma\vert{})$, where $\vert{}\Sigma\vert{} = 26$.

  The length of the first half is $N/2$. For each position, we try up to 26 characters. When calling getCount, thanks to the aggressive "early limit break," the inner loops often terminate within a handful of iterations, strictly bounding the time to a constant $O(26)$. The overall time complexity scales linearly, running at a blazing-fast limit (often 1~3ms in Java).

* Space Complexity: $O(\vert{}\Sigma\vert{}) = O(1)$.

  Excluding the space required to store the final output string, the entire process only utilizes fixed-size frequency arrays (size 26), making the memory footprint negligible.

Solution:

```
class Solution {
    public String smallestPalindrome(String s, int k) {
        int[] cnt = new int[26];
        int n = s.length();

        for (char c : s.toCharArray())
            cnt[c - 'a']++;

        for (int i = 0; i < 26; i++) cnt[i] /= 2;

        long totalPermutations = getCount(cnt, k);
        if (totalPermutations < k) return "";

        StringBuilder firstHalf = new StringBuilder();
        for (int i = 0; i < n / 2; i++) {
            for (int j = 0; j < 26; j++) {
                if (cnt[j] == 0) continue;
                cnt[j]--;

                long ways = getCount(cnt, k);

                if (ways < k) {
                    k -= ways;
                    cnt[j]++;
                } else {
                    firstHalf.append((char)(j + 'a'));
                    break;
                }
            }
        }

        return firstHalf.toString() + (n % 2 == 1 ? s.charAt(n / 2) : "") + firstHalf.reverse().toString();
    }

    private long getCount(int[] cnt, int limit) {
        int maxCount = -1, maxIndex = -1;
        for (int i = 0; i < 26; i++)
            if (maxCount < cnt[i]) {
                maxCount = cnt[i];
                maxIndex = i;
            }

        long ways = 1, len = maxCount;
        for (int i = 0; i < 26; i++) {
            if (i == maxIndex) continue;

            for (int j = 1; j <= cnt[i]; j++) {
                len++;
                ways = ways * len / j;
                if (ways > limit) return limit + 1;
            }
        }

        return ways;
    }
}

2nd Solution:

🌟 Core Insight: 

O(1) Math Transition & Reverse Prefix PeelingThe base problem reduces to finding the $k$-th lexicographically smallest permutation of the palindrome's first half. However, standard greedy approaches suffer from a fatal flaw: recalculating multiset permutations (factorials) for every single character trial is computationally expensive and highly prone to massive integer overflow.

Instead of arbitrarily capping the permutations to prevent overflow, we can use an elegant combination of Combinatorial Math and Reverse Peeling to achieve $O(1)$ state transitions.

🛠️ The Two-Phase Masterclass

Phase 1: Reverse Prefix Peeling (The Anti-Overflow Anchor)

If we try to calculate the permutations of the entire first half (up to 5000 characters), it will instantly overflow a 64-bit long. If we truncate it to prevent overflow, we lose the exact mathematical value required for $O(1)$ transitions later.

The Fix: We iterate backward from 'z' down to 'a'.We slowly accumulate the permutation count (ways) of these larger characters. The exact moment our accumulated ways reaches or exceeds $k$ (ways >= k), we hit the brakes!

* This establishes our "active suffix".
* Any characters smaller than our current one have absolutely zero mathematical chance of changing positions within the first $k$ permutations. They are permanently locked as a fixed prefix and can be batch-appended to our result immediately.
* Crucial Benefit: This gives us an exact, un-truncated ways that is safely bounded around $k$, completely eliminating the risk of overflow.

Phase 2: O(1) Algebraic State Transition

With a mathematically pure ways secured and our active suffix isolated, we can completely abandon factorial loops. We determine the number of permutations for a specific branch using a simple combinatorial reduction formula:

$$\text{branchWays} = \frac{\text{ways} \times \text{freq}[c]}{\text{remainingLength}}$$

By multiplying the upstream ways by the available frequency of the chosen character $c$, and dividing by the remaining length, we calculate the exact branch weight in $O(1)$ time.

* If branchWays >= k: The $k$-th permutation must start with this character. We lock it in, and our total ways instantly updates to branchWays (ways = branchWays).
* If branchWays < k: We safely skip this branch and deduct it from our target (k -= branchWays).

⏱️ Complexity Analysis
* Time Complexity: $O(N \times \vert{}\Sigma\vert{})$, where $\vert{}\Sigma\vert{} = 26$.

  By mathematically eliminating the need to iterate through factorials, the heavy lifting is reduced to basic arithmetic (* and /). The prefix is batched in linear time, and the greedy trial takes at most a few operations per position. The execution time approaches absolute zero overhead (0-1ms in Java).

* Space Complexity: $O(\vert{}\Sigma\vert{}) = O(1)$.
  Aside from the StringBuilder used for the output, we only utilize a fixed-size integer array of length 26 to track frequencies.

```
class Solution {
    public String smallestPalindrome(String s, int k) {
        int[] cnt = new int[26];
        for (char c : s.toCharArray()) cnt[c - 'a']++;
        for (int i = 0; i < 26; i++) cnt[i] /= 2;

        int n = s.length();
        int activeLen = 0;
        long ways = 1L;
        StringBuilder firstHalf = new StringBuilder();

        outer:
        for (int i = 25; i >= 0; i--) {
            for (int j = 1; j <= cnt[i]; j++) {
                activeLen++;
                ways = ways * activeLen / j;

                if (ways >= k) {
                    for (int c = 0; c < i; c++) {
                        while (cnt[c]-- > 0)
                            firstHalf.append((char)(c + 'a'));
                    }

                    while (cnt[i] > j) {
                        firstHalf.append((char)(i + 'a'));
                        cnt[i]--;
                    }

                    break outer;
                }
            }
        }

        if (k > ways) return "";

        for (int i = 0; i < activeLen; i++) {
            for (int j = 0; j < 26; j++) {
                if (cnt[j] <= 0) continue;
                
                long branchWays = ways * cnt[j] / (activeLen - i);

                if (branchWays >= k) {
                    firstHalf.append((char)(j + 'a'));
                    cnt[j]--;
                    ways = branchWays;
                    break;
                } else {
                    k -= branchWays;
                }
            }
        }

        String left = firstHalf.toString(), right = firstHalf.reverse().toString(), mid = n % 2 == 1 ? String.valueOf(s.charAt(n / 2)) : "";

        return left + mid + right;
    }
}
