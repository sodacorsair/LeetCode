You are given an integer array nums and two integers a and b.

For a subarray, let:

x be the number of even elements.
y be the number of odd elements.
The ratio of even to odd elements in a subarray is defined as x / y, where ratios are compared by their exact rational values.

A subarray is considered valid if:

y > 0, and
x / y <= a / b.
Return the number of valid subarrays in nums.

 

Example 1:

Input: nums = [1,2,1,2], a = 3, b = 2

Output: 7

Explanation:

The following are the valid subarrays:

Subarray	Values	Even Count	Odd Count	Ratio

nums[0..0]	[1]	0	1	0 / 1
nums[0..1]	[1, 2]	1	1	1 / 1
nums[0..2]	[1, 2, 1]	1	2	1 / 2
nums[0..3]	[1, 2, 1, 2]	2	2	2 / 2
nums[1..2]	[2, 1]	1	1	1 / 1
nums[2..2]	[1]	0	1	0 / 1
nums[2..3]	[1, 2]	1	1	1 / 1

Thus, the number of valid subarrays is 7.

Example 2:

Input: nums = [2,2,1], a = 2, b = 1

Output: 3

Explanation:

The following are the valid subarrays:

Subarray	Values	Even Count	Odd Count	Ratio

nums[0..2]	[2, 2, 1]	2	1	2 / 1
nums[1..2]	[2, 1]	1	1	1 / 1
nums[2..2]	[1]	0	1	0 / 1

Thus, the number of valid subarrays is 3.

Example 3:

Input: nums = [2,2,2], a = 1, b = 1

Output: 0

Explanation:

Every subarray contains 0 odd numbers, so no subarray is valid.

 

Constraints:

1 <= nums.length <= 105
1 <= nums[i] <= 109
1 <= a, b <= 109

Thought:

## 💡 Intuition & Approach

At its core, this problem asks us to find subarrays that satisfy a specific ratio constraint and contain at least one odd number. By applying a clever mathematical transformation, we can reduce this complex subarray counting problem into a classic **"Prefix Sum + Fenwick Tree"** model.

### 1. Mathematical Transformation (The Core Trick)
Let $x$ be the number of even elements and $y$ be the number of odd elements in a subarray.
The problem requires: 
$ \frac{x}{y} \le \frac{a}{b} \quad \text{and} \quad y > 0 $

Since $y > 0$ and $b \ge 1$, we can safely cross-multiply to avoid floating-point issues:
$ x \cdot b \le y \cdot a $
Rearranging the inequality gives:
$ y \cdot a - x \cdot b \ge 0 $

This formulation reveals a brilliant mapping strategy. We can assign a specific "weight" to each element in the array:
* If the element is **Odd**: Assign a weight of **$+a$**.
* If the element is **Even**: Assign a weight of **$-b$**.

With this mapping, a subarray is valid if and only if its **sum is $\ge 0$**. 
*(Bonus: What if the subarray has only even numbers? $y=0$, the sum would be strictly negative (since $-b < 0$), automatically filtering out invalid cases without needing an explicit check!)*

### 2. Prefix Sums & Fenwick Tree
Let `pre` be the prefix sum array of our mapped weights. The sum of a subarray from index $j$ to $i-1$ is given by `pre[i] - pre[j]`. 
For a valid subarray, we need:
$$ pre[i] - pre[j] \ge 0 \implies pre[j] \le pre[i] \quad (\text{where } j < i) $$

The problem is now reduced to: **As we iterate through the prefix sums, how many previously seen prefix sums are less than or equal to the current prefix sum?**

### 3. Algorithm Steps
1. **Build Prefix Sums:** Compute the prefix sum array using the $+a$ and $-b$ mapping. Remember to include a `0` at the beginning (`pre[0] = 0`).
2. **Coordinate Compression (Discretization):** The prefix sums can be extremely large or small. We copy the prefix sums, sort them, and remove duplicates to assign each unique value a dense `1`-based rank.
3. **Count using Fenwick Tree (BIT):** 
   * Initialize a Fenwick Tree with the size of the unique ranks.
   * Iterate through the original `pre` array.
   * For each `pre[i]`, find its `rank`.
   * Query the Fenwick Tree for the sum up to `rank`. This tells us how many valid starting points `j` exist for the current end point `i`. Add this to the total answer.
   * Update the Fenwick Tree by inserting the current `rank` with a frequency of `1`.

### ⏱️ Complexity Analysis
* **Time Complexity:** $\mathcal{O}(N \log N)$. Sorting the prefix sums takes $\mathcal{O}(N \log N)$. Iterating through the array and querying/updating the Fenwick tree takes $\mathcal{O}(N \log N)$.
* **Space Complexity:** $\mathcal{O}(N)$. We need arrays for the prefix sums, the sorted unique values, and the Fenwick tree, all of which scale linearly with the input size.

* Solution:

* ```
  class Solution {
    class FenwickTree {
        int[] tree;
        int n;

        public FenwickTree(int n) {
            tree = new int[n + 1];
            this.n = n;
        }

        public void update(int x, int val) {
            while (x <= n) {
                tree[x] += val;
                x += x & -x;
            }
        }

        public int query(int x) {
            int sum = 0;
            while (x > 0) {
                sum += tree[x];
                x -= x & -x;
            }

            return sum;
        }
    }

    public long countRatioSubarrays(int[] nums, int a, int b) {
        int n = nums.length;
        long[] pre = new long[n + 1];

        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + (nums[i] % 2 == 0 ? -b : a);

        long[] arr = pre.clone();
        Arrays.sort(arr);
        int cnt = 0;
        for (int i = 0; i <= n; i++) {
            if (i == 0 || arr[i - 1] != arr[i]) arr[cnt++] = arr[i];
        }

        FenwickTree bits = new FenwickTree(cnt);
        long ans = 0;
        for (int i = 0; i <= n; i++) {
            int rank = getRank(arr, pre[i], cnt);

            int x = bits.query(rank);
            ans += x;

            bits.update(rank, 1);
        }

        return ans;
    }

    // 1-indexed
    private int getRank(long[] pre, long val, int len) {
        int lo = 0, hi = len - 1;
        while (lo < hi) {
            int mi = (hi - lo) / 2 + lo;
            if (pre[mi] >= val) hi = mi;
            else lo = mi + 1;
        }

        return lo + 1;
    }
}
```
